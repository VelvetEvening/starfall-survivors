# 当前游戏机制

更新日期：2026-09-11
适用范围：本地单机 v1 基线及线上化拆分前的共享规则参考

## 1. 技术与单局流程

- 原生 JavaScript + Canvas 2D，运行时零包依赖；音频由 WebAudio 合成。
- 逻辑坐标固定为 480×270，显示缓冲可按窗口和像素密度放大；渲染倍率不改变碰撞、射程、移动和数值。
- 一局倒计时 8 分钟：4:00 进入 BOSS1，8:00 进入 BOSS2；击杀最终 BOSS 胜利，死亡或其它结束条件进入结算。
- 主循环使用固定 1/60 步长；输入在逻辑步末消费，暂停、升级、星图等面板状态暂停战斗资源更新。
- 常规武器自动攻击；电磁炮由鼠标点击瞄准发射。当前正式支持电脑键盘和鼠标，小窗口适配不等于触屏支持。

## 2. 目录到机制的映射

- src/data/ 是策划表：角色、武器、被动、敌人/BOSS 攻击和配置常量。
- src/sim/ 执行投射物、武器、敌人、BOSS、波次和掉落；src/growth/ 聚合玩家属性、升级和专精矩阵。
- src/engine/game.js 管理状态机、时间、经验、结算和局内事件；src/ui/ 只处理面板与反馈；src/render/ 只负责表现层。
- src/core/save.js 是唯一持久化出口。当前实现是 LocalStorage；线上化时替换为带 Session 的 ServerLayer，不能在 UI 或战斗代码中另写存档。

## 3. 四机体

对外名称为焰锋、霜翎、磁暴、铁壁；内部 ID vega、firefly、thunder、dawn 和存档键必须保留。

- 焰锋：全火系共享计热，达到 15 格后按空格开启 15 秒超载；超载期间不计热，常态与超载灼烧独立叠层。
- 霜翎：每 5 秒获得周期防反窗口；成功防反时伤害归零并准备下一发强化霜棱弹，冰系命中可叠冰蚀；BOSS 不被冻结。
- 磁暴：电磁炮普通单发与满仓三发聚能有专属倍率；一次点击严格消耗一发或满仓，停滞期间不缓存点击。
- 铁壁：护盾实吸伤害积累震荡值，达到阈值且冷却就绪才释放全周震荡；震荡与盾盘强化分开结算。

角色机制的详细回归证据见 CHARACTER_UPDATE.md 与 gui-test-screenshots/characters/logic-audit.json；新增机制必须同时补测试和反馈。

## 4. 武器、升级与专精

- 武器通过自动攻击、冷却、蓄力、穿透、灼烧、冻结、冰蚀和进化构成 Build；武器升级和进化不能让每发伤害或全命中 DPS 倒退。
- 升级三选一在升级面板完成；宝箱优先进化，无法进化时给一次升级选择并增加专精点。同帧获得经验时，进化完成后继续处理排队的升级，再恢复战斗。
- 四条专精矩阵各 6 节点、本系总成本 20；本系消耗乘 1，异系消耗乘 2。矩阵效果先聚合，再由 player.recalcStats 结算派生属性。
- 持有对应超武后，被动联动效果会追溯已获得层数；进化后必须重新计算派生属性。
- 装甲工坊为局外强化：生命、速度、伤害各 5 级，初始武器购买 5 次后按 Lv.6 入场；旧档 ID 和 weapon=5 语义保持兼容。

## 5. 敌人和 BOSS

- 常规出怪从玩家附近生成，频率随时间按平滑曲线变化；精英在固定时间点出现并提供宝箱/高价值星尘。
- BOSS1 与 BOSS2 的召唤技能只在自身边缘生成召唤精英，不夹带普通小怪；同屏召唤精英有上限。
- BOSS 战另外由波次导演每 30 秒从玩家四周生成环境小怪：BOSS1 每波 15 只，BOSS2 每波 20 只。这些实体带 noRewards，死亡不产经验、道具、分数，也不计击杀统计；分裂实体必须继承该标记。
- BOSS1 存活时小怪血量停在第一段曲线终点；击杀事件触发后才跳升，不能用浮点计时是否略超 240 秒代替击杀状态。
- BOSS2 50% 血量进入狂怒二阶段，二阶段技能按 phase2Only 过滤；转阶段首次释放深渊停滞。BOSS 不冻结，减速只部分生效，灼烧仍可生效。
- 接触伤害、敌弹、冰冻易伤、冰蚀、护盾、破盾保护和角色防反都在实体伤害收口处保持明确的免疫/乘区语义。

## 6. 反馈与表现约定

- 顶部 toast 只显示 BOSS、精英和怪潮警告；系统内提示使用音效、粒子、HUD 或面板。
- 普通小怪弹为红色，精英/BOSS 高危弹为金色，BOSS2 高伤或强化精英弹为深暗红；颜色必须和实际伤害等级一致。
- 世界层绘制使用 renderer 坐标 helper，绘制 UI 前切换到 R.beginUI()；粒子统一由粒子模块进行世界到屏幕换算。
- 状态视觉必须与机制一致：不吃冻结的实体不得画冻结效果，BOSS 受折扣减速时显示淡冰圈。

## 7. 存档与线上拆分边界

本地版的 localStorage 只适合单机试玩，不能提供跨设备同步、可信排行榜或防作弊。线上版本必须把身份、资产、对局结算和排行迁移到服务器；客户端可以预测表现，但不能覆盖服务器快照。

最高分按难度分桶保存。仅缺少 bestScores 的旧档会把 bestScore 迁入正常难度；新档的 bestScore 是跨难度兼容字段，重载不得覆盖正常难度纪录。已被旧逻辑串改的历史纪录缺少原始分数，不能自动还原。

线上实施顺序、账号安全、WebSocket、确定性模拟和发布验收见仓库外层 ONLINE_ROADMAP.md。
